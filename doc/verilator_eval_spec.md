## Verilator による BitPack の評価に関する仕様

この文書は，Verilator によるシミュレーションを用いて BitPack を用いた
Stochastic Computing 回路の評価を行う際にあたり，必要な仕様を定義するものである．

### 前提とするツール・ライブラリなど

Ubuntu 環境であれば，これらはいずれも apt で入手可能．

- `verilator`
- `build-essential`（g++ のために）
- `nlohmann-json3-dev`

### 事前に必要なファイル一式

Verilator によるシミュレーションを行う場合，カレントディレクトリに以下のファイル・フォルダを用意する．

- `hdl`: フォルダ．ユーザ回路（ファイル名は任意），および `code_generator/bitpack_gen.py` で生成した以下のファイルを含む
  - `user_wrapper.sv`: ラッパ回路であり，これがシミュレーションでは UUT となる
  - `sn_gen.sv`: Stochastic Number の生成回路
  - `count.sv`: カウンタ（出力の Stochastic Number から元の実数値を得るために用いる）
- `testbench`: フォルダ．C++ テストベンチのソースコードを含む
  - `bitpack_test.cpp`: テストベンチ本体
  - `bitpack_lib_rand.cpp`，`bitpack_lib_rand.hpp`: 再現性のある疑似乱数のためのライブラリ
  - その他必要なクラス群の定義と実装（詳細は `doc/verilator_eval_classes.md`）
- `eval.json`: 評価のための設定ファイル（仕様は `doc/eval_json_spec.md`）
- `Makefile`: 一連のビルド手順を記した Makefile

### ビルド手順

1. Verilator を使って，`hdl` フォルダの SystemVerilog 記述をもとに，`verilated` フォルダに
   `Vuser_wrapper.cpp` などの C++ ソースコードと，関連するファイルを生成する
2. `Vuser_wrapper.mk` を使って `verilated` フォルダのコードをビルドし，
   同フォルダに `libVuser_wrapper.a` などのライブラリを作成する
3. 2で作成したライブラリと `testbench` フォルダのコードを組み合わせてビルドし，
   実行ファイル `bitpack_eval` を作成する

### トップモジュール user_wrapper について

実機評価では，このモジュールは AXI-Lite のメモリマップト I/O `AXI_CTRL` と，
フル機能の AXI コントローラ `AXI_FIFO` に接続される．
テストベンチでは，これらの信号を直接操作する．

メモリマップト I/O から `user_wrapper` に入出力される信号は，以下のとおりである．
- `GO`: アイドル時にこの信号が '1' に立上ることによって，回路は動作開始する
        （回路の動作終了後は，`GO` が '0' かどうかを確認してから，アイドル時に戻る）
- `DONE`: アイドル時に限り '1' を出力する
- `SRC`: 入力配列の読み出し先アドレス
- `DST`: 出力配列の書き込み先アドレス
- `SIZE`: ユーザ回路が何クロックサイクル動作するか（= `eval.json` の `"cycle"`）

この定義から，回路の動作開始・終了のハンドシェイクは，以下のようなシンプルなものとなる．
1. `DONE` が '1' であることを確認して，`GO` を '1' にする
2. 次のサイクル以降，`GO` を '0' にして，`DONE` が '1' になるのを待つ

なお，`SRC`，`DST` は AXI コントローラが使用するアドレスであるため，テストベンチでは意味をもたない．
単に 0 を入力しておけばよい．

AXI コントローラは，4種類の FIFO をもつ．
これらはおおむね AXI の AR，R，AW，W チャネルに対応する．
書き込みの成否はチェックしないので，B チャネルに対応する FIFO は存在しない．
これらの FIFO の主な目的は，AXI のバースト転送の長さ（`ARLEN` や `AWLEN`）に関する制限の隠蔽である．
（AXI の1回の転送は最大 256 ワードだが，このコントローラは最大 65,535 ワードの転送を受け入れる）

各 FIFO とのインタフェースのための信号は，以下のとおりである．

- AR チャネルに相当
  - `READ_ADDR`: 読み出し先アドレス（テストベンチでは意味をもたない）
  - `READ_COUNT`: 読み出しワード数
  - `READ_REQ`, `READ_BUSY`: 転送のハンドシェイク
- R チャネルに相当
  - `READ_DATA`: 読み出しデータ
  - `READ_VALID`, `READ_READY`: 転送のハンドシェイク
- AW チャネルに相当
  - `WRITE_ADDR`: 書き込み先アドレス（テストベンチでは意味をもたない）
  - `WRITE_COUNT`: 書き込みワード数
  - `WRITE_REQ`, `WRITE_BUSY`: 転送のハンドシェイク
- W チャネルに相当
  - `WRITE_DATA`: 書き込みデータ
  - `WRITE_VALID`, `WRITE_READY`: 転送のハンドシェイク

ハンドシェイクはおおむね AXI の規約と同様で，`*_VALID` と `*_READY` がともに '1' ならデータ転送成立となる．
ただし，アドレスについては `*_BUSY` と `*_READY` とでは極性が反転する．
つまり，`*_REQ` が '1' でかつ `*_BUSY` が '0' ならアドレス転送成立となる．

`user_wrapper` の内部ロジックは，1回の回路動作ごとに以下の処理を行う．
- ユーザ回路の入力の数（`src_size`）だけ，入力の構造体を読み取る
- ユーザ回路を `SIZE` で指定されたサイクル数だけ動作させる
- ユーザ回路の出力の数（`dst_size`）だけ，出力のカウンタ値を書き込む

入力の構造体は，以下の通り定義される．
この構造体は2つの32ビットワードで構成されるので，実際に `user_wrapper` によって読み取られるワード数は，`src_size` の2倍となることに注意．

```C++
#include <stdint.h>
typedef struct {
    int32_t  binary_value;
    uint32_t seed;
} input_port_t;
```

`binary_value` は，入力が負の値を取りうる（`eval.json` の `"has_negative"` が真）なら`INT_MIN` ～ `INT_MAX` を，
非負の値だけを取るなら 0 ～ `INT_MAX` をとる．
入力の実数値が `"denominator"` の値や 0 である場合，`binary_value` はそれぞれ `INT_MAX` や 0 にマップされる．
例えば，`"has_negative"` が真，`"denominator"` が 1.0 である，
つまり入力が -1.0 ～ 1.0 の実数値を取りうる場合，入力値と `binary_value` の関係の例は以下の通りである．

|入力値|`binary_value`|
|------|--------------|
|  1.0 | `0x7fffffff` |
|  0.5 | `0x3fffffff` |
| -0.25| `0xe0000000` |
| -1.0 | `0x80000000` |

`seed` には，32ビット符号なしの疑似乱数を与える．
これには，`eval.json` の `"seed"` をシードとして初期化された `BitPackRandom` インスタンスを用いる．
`BitPackRandom` インスタンスは，評価全体を通じて 1 個だけ作成し，
`"times"` 周すべての回路動作で使い回すものとする（各周や各組合せで再初期化しない）．
ただし，LFSR の初期状態が全 0 になると出力が固定値になるため，
抽選結果が 0 だった場合は 1 回だけ再度抽選を行い，0 でない値を `seed` として用いるものとする．

出力は，32ビット符号つき整数のカウンタ値として与えられる．
得られたカウンタ値を `SIZE * denominator` で割ることで，実数値に変換できる．


### 入力の組合せについて

テストベンチでは，`eval.json` の記述内容をもとに，`user_wrapper` を指定された回数だけ繰り返し動作させる．
入力の値のすべての組合せに対して，1回ずつ回路を動作させることを1周とする．
テストベンチでは，これを `"times"` 周だけ繰り返す．

このとき，ランダムな値を使う入力（`"random"` が真）がない場合，
入力の値のすべての組合せとは，入力の値の候補の集合（`"values"`）に対してデカルト積を取ったものとなる．
ランダムな値を使う入力がある場合，その入力に対する値の候補の集合は，
「ランダムな値を使う」という特別な値（ここでは `USE_RANDOM` とする）だけを含むとみなす．

例えば，回路が3つの入力 A, B, C をもち，それぞれの `"random"` と `"values"` が，
```json
[{"random": false, "values": [0.0, 0.5, 1.0]},
 {"random": true,  "values": []},
 {"random": false, "values": [0.25, 0.75]}]
```

であったとする．この場合，テストベンチの1周では，以下の6通りの入力の組合せを試行する．
- [0.0, `USE_RANDOM`, 0.25]
- [0.0, `USE_RANDOM`, 0.75]
- [0.5, `USE_RANDOM`, 0.25]
- [0.5, `USE_RANDOM`, 0.75]
- [1.0, `USE_RANDOM`, 0.25]
- [1.0, `USE_RANDOM`, 0.75]

組合せの出現順序は，Python の `itertools.product` でデカルト積を求めた場合と一致することが望ましい．

各入力の組合せを `user_wrapper` が読み取るデータに変換する際，`seed` だけではなく `USE_RANDOM` が指定された入力値のためにも，疑似乱数が必要となる．
これには，`seed` を生成するために使うのと同じ `BitPackRandom` インスタンスを用いる．
疑似乱数は，まず `USE_RANDOM` が指定された入力すべてに値を与えるために使用する．
すべての入力値が決まってから，`seed` の生成を行う．
つまり，上述の A, B, C の例であれば，B の入力値，A のシード，B のシード，C のシードの順に疑似乱数を使う．
`USE_RANDOM` が指定された入力の `binary_value` は，抽選した疑似乱数そのものを用いる．
ただし，`"has_negative"` が偽の場合は上位 1 ビットをクリアしたもの（0 ～ `INT_MAX` の範囲）を用いる．
固定値（`"values"` から選ばれた値）が `[-denominator, denominator]`（`"has_negative"` が偽の場合は `[0, denominator]`）の範囲を超えている場合，
近い端の値に丸めてから `binary_value` へ変換するものとする．

### テストベンチの出力

テストベンチは，以下の3種類のログファイルを出力するものとする．
- `results.txt`: 回路の各入力・出力の実数値を，1回の回路動作につき1行で並べたもの
- `input.txt`: `user_wrapper` から読み取られたワードの値を，1ワードにつき1行，16進数8桁で並べたもの
- `output.txt`: `user_wrapper` から書き込まれたワードの値を，1ワードにつき1行，16進数8桁で並べたもの

`results.txt` は演算精度の評価のために，残りの2つは実機検証時との比較・デバッグのために，それぞれ用いられることを想定している．

3つのファイルは，評価開始時に新規作成（上書き）するものとする．
`input.txt` と `output.txt` は，`"times"` 周すべての回路動作で読み取られた・書き込まれたワードを，
回路動作の順序（および 1 動作内では `user_wrapper` が読み書きする順序）に沿って連続して書き出すものとする．

`results.txt` の各行は，`eval.json` の `"input"` に従う入力の順序で各入力の（実数値としての）入力値を並べ，
その後，`"output"` に従う出力の順序で各出力の実数値（カウンタ値を `SIZE * denominator` で割った値）を並べたものとする．
各値は半角空白で区切り，1 行の末尾は改行とする．
